# LOA ROGUE — Codex 통합 개발 명세 v1.0

> 본 문서는 기존 대화에서 확정된 게임 규칙을 통합한다. 로스트아크 명칭과 캐릭터는 기획용이며, 외부 배포 시 권리자 허락을 확인한다. 원작 게임의 모델·음원·이미지·코드 무단 추출 금지. 개발에는 독자 플레이스홀더를 사용한다.

## 1. 제품 목표 및 기술
- 모바일 브라우저 중심 가로 모드, React + TypeScript + Vite + React Three Fiber/Three.js + Zustand.
- 단일 사용자 진행형 1~100층 로그라이크 RPG. 전투는 아군 1명 대 적 1명, 예비 영웅 교체.
- 개인 MacBook Pro(Mid 2015)를 서버로 사용. Node.js LTS(실제 설치 가능 버전 확인) + Fastify + SQLite(WAL), HTTPS reverse proxy/tunnel. Firebase 금지.
- 계정별 이메일·비밀번호·닉네임 회원가입, 로그인, 로그아웃, 세션, 진행 저장, 결과 기록.
- 외부 접속은 Cloudflare Tunnel 등으로 구성 가능하되 실제 도메인 및 설정값은 환경변수로 처리. 노트북 종료/절전 시 서비스 중단. 주기적 SQLite 안전 백업.

## 2. 핵심 게임 루프
로그인 → 영구 성장 로비 → 코스트 기반 시작 파티 선택 → 층 이벤트 후보 3개 → 선택 이벤트 진행 → 전투/상점/휴식/대장간/보물/미지의 균열 → 층 클리어 보상 → 다음 층 → 10층 단위 보스 → 100층 클리어 또는 전멸/포기 → 아크의 결정 지급 → 영구 강화 → 재도전.
- 층은 1~100이며 10,20,...,100층은 고정 보스. 20층 단위로 지역과 적 풀 변경.
- 일반 층 이벤트 후보 3종은 서버가 시드 기반으로 중복 없이 생성하고 영구 저장; 새로고침 시 재추첨 금지.
- 일반/정예 전투, 휴식, 상점, 대장간, 보물방, 미지의 균열 이벤트 지원. 후보 가중치는 설정 파일에서 변경 가능.
- 도전 중 골드/레벨/장비/소모품/유물은 종료 시 초기화. 계정 아크의 결정, 영웅 강화, 코스트 감소, 제작법 도감, 전투 기록은 영구 보존.

- 6명 모두 최초 계정에서 선택 가능. 1~6명 편성 가능, 현재 코스트 합계 ≤ 15. 중복 영웅 편성 금지.
- 코스트 = max(최소 코스트, 기본 코스트 - 영구 감소 단계). 시작 파티 확정 후 해당 도전 중 코스트 변경 불가.
- 편성 첫 슬롯이 선봉. 살아있는 대기 영웅과 교체. 강제 교체는 행동 소모 없음; 자발적 교체는 1턴 행동 소모.
- 영웅은 기본 공격 1, 일반 스킬 2, 궁극기 1, 패시브 1. 상세 스킬 수치/쿨타임은 별도 데이터 테이블에서 관리하며 플레이스홀더 구현 시 영웅별 차별화 필수.

## 4. 턴제 전투 엔진
- 전투는 1대1 필드. 적은 연속 출전하는 최대 3개체 파티를 구성할 수 있음; 동시 출전은 항상 1개체.
- 플레이어 행동: 기본 공격, 스킬(2종), 궁극기(게이지 100), 아이템 사용, 영웅 교체.
- 행동 우선순위: 강제 교체 > 자발적 교체 > 일반 행동; 동순위는 SPD 비교, 동속도는 저장 시드 기반 결정.
- 피해 공식(초기안): max(1, floor((skillPower*ATK/(ATK+0.6*DEF))*modifier*random(0.95~1.05))). 치명타 기본 1.5배. 스킬·속성 배율과 방어는 데이터 기반.
- 무력화 게이지 0 시 다음 행동 1회 봉쇄, 이후 회복. 보스는 무력화 종료 후 2턴 면역.
- 상태이상: 화상(턴 종료 피해), 출혈(턴 종료 피해), 기절(행동 불가), 속도 감소, 보호막. 중첩 및 지속 시간은 명시적 데이터.
- 서버가 전투 계산의 유일한 권한자. 클라이언트는 행동 요청을 보내고 서버 이벤트 로그로 애니메이션 재생. 공통 순수 TypeScript 전투 규칙 모듈에 단위 테스트.
- 전투 중 재접속 시 마지막 서버 확정 상태 복구. 행동 actionId 멱등성 보장.

## 5. 100층 구성
- 1~20 루테란: 인간형·야수·악마; 20층 발탄(기획용).
- 21~40 로헨델: 정령·식물·마법; 40층 비아키스(기획용).
- 41~60 페이튼: 악마·언데드; 60층 쿠크세이튼(기획용).
- 61~80 엘가시아: 빛·환영·수호자; 80층 아브렐슈드(기획용).
- 81~100 균열 심층부: 혼돈·강화 악마; 100층 독자 최종 보스.
- 매 10층 보스 10종, 일반 30종, 정예 10종 총 50종 몬스터 데이터. 초반에는 공통 리깅과 색상/장비 변형을 활용해 3D 모델 재사용.
- 적 AI 유형: 공격형, 방어형, 상태이상형, 회복형, 무력화형, 광폭형, 패턴형. 층별 레벨/스탯 스케일링 설정 가능.
- 보스는 전용 패턴 예고, 체력 구간 페이즈, 무력화 기믹. 최소 10종 데이터 완비.

## 6. 장비 및 제작
- 장비: 영웅당 무기/방어구/장신구 각 1슬롯, 파티 공유 유물 2슬롯.
- 등급: 일반→고급→희귀→영웅→전설, 유물은 별도. 일반 등급 합성은 같은 등급 장비 3개를 소비하여 다음 등급 1개 생성, 성공률 100%, 유물은 일반 합성 불가.
- 합성 재료는 도전 인벤토리에 실제 소유한 미장착 장비 3개. 서버에서 중복 장비 ID·등급·소유권 검증, 하나의 트랜잭션으로 삭제 및 결과 생성.
- 특수 조합: 지정 장비/재료를 소모하여 레시피 결과 생성. 발견 레시피는 계정에 영구 기록, 결과 장비는 도전 한정.
- 획득처: 전투, 정예, 보스, 보물방, 상점, 랜덤 이벤트, 대장간. 장비 능력치 및 옵션은 시드 기반 서버 생성.
- 장비의 장착/해제는 비전투 상태에서만 허용. 인벤토리 용량 기본 60칸(밸런스 조정 가능); 꽉 찬 경우 수령 전 분해/버리기 UI.

## 8. 영구 재화와 강화
- 던전 골드(도전 한정)와 아크의 결정(계정 영구)을 분리.
- 전멸 시 기본 보상 = 10 × 최고 도달 층수. 100층 클리어 시 기본 1000 + 클리어 보너스 500 = 1500, 최초 클리어 추가 1000(1회). 중도 포기 시 마지막 완료 층의 10배에서 50% 지급(내림). 진행 중 네트워크 끊김은 포기가 아니며 재개 가능.
- 영웅별 영구 강화: HP(레벨당 +2%, 최대 20), ATK(+1.5%, 최대 20), DEF(+1.5%, 최대 20), 치명타 확률(+0.5%p, 최대 10), SPD(+0.5%, 최대 10). 초기 비용 = 50×(현재 강화 레벨+1)^2.
- 코스트 감소: 영웅별 1회 500, 2회 1500, 3회 3500 결정. 기본/최소 코스트 차이만큼만 구매 가능.
- 서버는 잔액, 상한, 이전 구매 단계, actionId를 검증하고 원자적 차감+업데이트. 클라이언트에서 재화 계산 결과를 신뢰하지 않음.

- 스키마는 migration 파일로 관리. SQLite WAL, busy_timeout, DB 경로 환경변수, 정기 backup API 활용.

## 12. 보안 및 배포
- Argon2id 해시, 안전한 세션 쿠키(HttpOnly, Secure, SameSite), CSRF 방어, CORS 제한, 로그인 속도 제한, 요청 크기 제한.
- 모든 API에서 user_id를 세션에서 획득하고 run 소유권 검사. 서버에서 보상, 전투, 아이템, 강화 결정.
- `.env.example` 제공: PORT, DATABASE_PATH, SESSION_SECRET, PUBLIC_ORIGIN, NODE_ENV 등. 실제 비밀값 Git에 커밋 금지.
- 개인 서버에서 프론트 정적 빌드와 API 함께 서비스; localhost 로컬 테스트 후 HTTPS 터널 공개. 백업, 로그 로테이션, 프로세스 재시작, 절전 방지 운영 안내.
- 서버 운영 중단과 네트워크 끊김 시 진행 복구 UX. 과금·광고·멀티플레이·랭킹은 범위 제외.
