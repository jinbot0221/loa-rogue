## 진단 및 수정

- 기존 테스트의 도전 시작 즉시 전투 가정은 이벤트 선택 단계를 거치도록 수정. 이전 활성 도전 호환도 별도 검사.
- 복수 레시피 조회는 SQL 순서에 의존하지 않고 전체ID 집합과 제작 결과를 검증.
- 최초 브라우저 실행에서 도감 필터의 정확한 접근성 이름 문제를 발견해 명시 aria-label 추가.
- 여러 화면을 빠르게 사용하는 전체 세션이 공통120회/분 제한에 걸려300회/분으로 조정. 인증은 각10회/분 유지. 실제 제한 동작을 별도 검사하며 테스트에서 끄지 않았다.
- 클라우드의 기존 DB는 runs 테이블이 없는 이전 스키마여서 첫 사전 행수 점검이 실패했다. migration 적용 후 현재 DB를 백업하고 테이블 존재를 확인하는 방식으로 반복 적용/행수/무결성을 검사했다. 이는 최초 적용 전 백업이 성공했다는 뜻이 아니다. 기존 계정/도전 보존은 별도 실제 SQLite fixture에서 검증했다.

## 한계와 남은 작업

데이터/실제 API 연결을 검증했으며100층 전체 플레이 완주나 최종 밸런스 검증은 아니다.100층 경계/일부 희귀 상태는 DB fixture로 구성한다. 실제 MacBook/휴대전화 GPU/외부 HTTPS/도메인 운영은 클라우드 테스트에 포함되지 않는다.

모델은6가지 자체 저폴리곤 도형을 재사용하는 플레이스홀더이며 원작 에셋을 사용하지 않는다. Three/R3F 지연 로딩 청크 크기 경고, Zod Rollup 주석 경고, Node SQLite 실험 경고는 남아 있으나 빌드/테스트는 성공한다. 영구 강화·코스트 감소 구매/계정 삭제는 이번 요청 범위 밖으로 남는다. 클라우드 환경 버전은 게시하지 않았다.
